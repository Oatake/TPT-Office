## Fonts (all from `brand/assets/fonts/`, auto-loaded by `scripts/build-pdf.mjs`)
| Font | Use | License | Credited on p.27 |
|---|---|---|---|
| Andika Regular/Bold (SIL International) | Body text, all digits (Andika digits are tabular, so tens/ones line up) | SIL Open Font License 1.1 | Yes |
| Fredoka (variable) (The Fredoka Project Authors) | Titles, card headers, cover, thumbnails | SIL Open Font License 1.1 | Yes (line added per the brief) |

- `pdffonts` check: the full PDF and the preview PDF contain **only Andika and Fredoka, all embedded and subset**. No system fonts.
- Chrome embeds the variable Fredoka as a Type 3 font named "Fredoka-Light" (the default instance name). This is normal for variable fonts. It prints correctly and the text can still be selected.
- The flavor lines are Andika with a synthetic italic. Andika has no italic file.
- **Theme issue (not fixed in the theme file, per the rules):** `playful-pop.css` draws `.directions::before` with a "★" glyph. Neither Fredoka nor Andika has that glyph, so Chrome would fall back to a system font and embed it in the PDF. This product overrides it with an original SVG star (`html .directions::before`). **Other products using `playful-pop` have the same problem.** Fix it once in the theme file, or add the same override to each product.
- The theme's "○ □ △ ☆" are not in Andika either, so every level icon is an inline SVG (`#lvl-1…4`). There are no glyph fallbacks.

## Art (all original inline SVG drawn for this product — no clip art, no third-party assets)
Every concept SVG is in **one hidden `<svg class="hidden-defs"><defs>` block** at the top of `worksheet.html` and is reused via `<use href="#id">`. For a seasonal reskin, swap the art there.
`hardhat`, `crane`, `rod`, `unit`, `signpost`, `cone`, `clipboard`, `checkbox`, `hazard` (pattern), `bpgrid` (pattern), `shield`, `clock`, `pencil`, `scissors`, `lvl-1…4`, `wave`, arrow markers.
- On student pages the hard hat is line-only (`--hat-fill` unset). The level icons are black line art, and base-ten blocks are navy lines on white. The hazard stripes and the blueprint grid appear only on the cover and thumbnails.
- Base-ten drawings (Crew Card, p.7 example, answer-key samples) are generated by `renderBT()` from small JSON specs, so the counts always match the math. Example: 52 − 27 shows 5 rods + 2 → trade → 4 rods + 12 → cross out 2 rods + 7 units.
- The Mystery Build grid (p.13) and the answer-key mini grid (p.23) come from the same `SHADE_GRID` / `SHADE_MAP` constants. I checked them by script before building: every shaded cell holds a correct answer and every unshaded cell holds a distractor (0 mismatches).
- `thumbnails.html` has a verbatim copy of the same defs block. If the art changes, update both.

## QA checks performed
- **Page count:** `pdfinfo` → 27 pages, letter. The preview has 8 pages (pp. 1, 3, 4, 9, 11, 13, 14, 16).
- **Overflow:** a layout script measured every page against the footer line. All 27 pages pass with no overflow and no title wider than its line. I opened page renders of every page, including the dense pages 4, 9, 10, 11, 13, 14, 15, 19, 20 and 23, and found no clipping.
- **Black and white:** I rasterized the full PDF in grayscale and checked it with contact sheets. Titles, directions, red answer-key text (bold) and the shaded mini grid all stay readable. Student pages have no large color or gray fills.
- **Writer check tables:** not printed anywhere. No C1/R1 labels on p.13. The word "house" does not appear on any student page. It appears only in the p.23 key, as the brief allows.
- **Thumbnails:** I checked each one at full size and at 250 px. No text overflows the canvas.
